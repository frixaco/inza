### Card Content Candidates

#### Concepts

- Rust's standard library includes useful data structures called collections.
- Most other data types represent one specific value.
- Collections can contain multiple values.
- Unlike built-in arrays and tuples, the data that collections point to is stored on the heap.
- Heap storage means the amount of data in a collection does not need to be known at compile time.
- Heap storage also lets collection data grow or shrink as the program runs.
- Different collections have different capabilities.
- Different collections have different costs.
- Choosing the appropriate collection for a situation is an important skill developed over time.
- CH-08 covers three collections that are used very often in Rust programs: vectors, strings, and hash maps.
- A vector stores a variable number of values next to each other.
- A string is a collection of characters.
- The `String` type has been mentioned previously, but CH-08 covers it in depth.
- A hash map associates a value with a specific key.
- A hash map is a particular implementation of the more general data structure called a map.
- The standard library documentation covers other collection types beyond this chapter.
- CH-08 will discuss how to create and update vectors, strings, and hash maps.
- CH-08 will also discuss what makes each of vectors, strings, and hash maps special.

### Card Content Candidates

#### Concepts

- `Vec<T>` is also known as a vector.
- Vectors store more than one value in a single data structure.
- Vectors put their values next to each other in memory.
- Vectors can only store values of the same type.
- Vectors are useful for lists such as file lines or shopping-cart prices.
- `Vec::new` creates a new empty vector.
- Empty vector creation often needs a type annotation because Rust cannot infer the element type from inserted values that do not exist.
- `Vec<T>` uses generics.
- `Vec<T>` can hold any one chosen element type.
- The element type is written inside angle brackets, such as `Vec<i32>`.
- The `vec!` macro creates a vector containing the values supplied to it.
- With initial values, Rust can infer the vector's element type.
- `vec![1, 2, 3]` creates a `Vec<i32>` because `i32` is the default integer type.
- `push` adds elements to a vector.
- A vector variable must be mutable if code will push values into it.
- Rust can infer an initially empty vector's type from later `push` calls in the same context.
- Vector elements are indexed from zero.
- `&v[2]` gives a reference to the third element.
- `v.get(2)` returns `Option<&T>`.
- `get` enables `match` handling of `Some(&element)` or `None`.
- Rust offers both `[]` and `get` so code can choose panic behavior or optional handling for out-of-range access.
- Out-of-range `[]` indexing panics.
- Out-of-range `get` returns `None` without panicking.
- `[]` access is appropriate when an out-of-range index should crash the program.
- `get` is appropriate when an out-of-range index can happen under normal circumstances and should be handled.
- The borrow checker applies normal ownership and borrowing rules to references into vector contents.
- You cannot have mutable and immutable references in the same scope.
- Listing 8-6 fails because `first` immutably borrows `v[0]`, then `v.push(6)` mutably borrows `v`, and `first` is used later.
- Pushing to a vector might require allocating new memory and copying old elements if there is not enough adjacent room in the current allocation.
- If reallocation happens, an old element reference could point to deallocated memory.
- Borrowing rules prevent references into a vector from becoming invalid after vector mutation.
- Iterating over vector elements is preferred when accessing each element in turn.
- `for i in &v` iterates over immutable references to vector elements.
- `for i in &mut v` iterates over mutable references to vector elements.
- To change the value behind a mutable reference, use the `*` dereference operator before assignment or `+=`.
- Iteration over vectors is safe because borrow-checker rules prevent simultaneous whole-vector modification.
- Inserting or removing items inside the loop body while iterating would produce a compiler error similar to Listing 8-6.
- The `for` loop holds a reference to the vector, preventing simultaneous modification of the whole vector.
- Vectors can only store one actual Rust type, but enum variants are all values of the enum type.
- An enum lets a vector hold different logical variants while still satisfying the same-type vector rule.
- Listing 8-9 uses `SpreadsheetCell` variants for `i32`, `f64`, and `String`.
- Rust must know all vector element types at compile time so it can know how much heap memory each element needs.
- Using an enum requires being explicit about the allowed set of value types.
- Combining enum variants with `match` lets Rust ensure every possible case is handled at compile time.
- If the exhaustive set of runtime types is not known, the enum technique will not work.
- Trait objects are the alternative for unknown runtime type sets and are deferred to Chapter 18.
- `Vec<T>` has many standard-library methods beyond this section.
- `pop` removes and returns the last element.
- A vector is freed when it goes out of scope.
- Dropping a vector drops all of its contents.
- The borrow checker ensures references to vector contents are only used while the vector itself is valid.

#### Syntax Forms

- Empty vector with explicit element type:
  ```rust
  let v: Vec<i32> = Vec::new();
  ```
- Vector with initial values:
  ```rust
  let v = vec![1, 2, 3];
  ```
- Mutable vector updated with `push`:
  ```rust
  let mut v = Vec::new();

  v.push(5);
  v.push(6);
  v.push(7);
  v.push(8);
  ```
- Indexing and `get`:
  ```rust
  let v = vec![1, 2, 3, 4, 5];

  let third: &i32 = &v[2];
  println!("The third element is {third}");

  let third: Option<&i32> = v.get(2);
  match third {
      Some(third) => println!("The third element is {third}"),
      None => println!("There is no third element."),
  }
  ```
- Out-of-range access forms:
  ```rust
  let v = vec![1, 2, 3, 4, 5];

  let does_not_exist = &v[100];
  let does_not_exist = v.get(100);
  ```
- Borrow-checker failure shape:
  ```rust
  let mut v = vec![1, 2, 3, 4, 5];

  let first = &v[0];

  v.push(6);

  println!("The first element is: {first}");
  ```
- Immutable iteration:
  ```rust
  let v = vec![100, 32, 57];
  for i in &v {
      println!("{i}");
  }
  ```
- Mutable iteration:
  ```rust
  let mut v = vec![100, 32, 57];
  for i in &mut v {
      *i += 50;
  }
  ```
- Enum variants in one vector:
  ```rust
  enum SpreadsheetCell {
      Int(i32),
      Float(f64),
      Text(String),
  }

  let row = vec![
      SpreadsheetCell::Int(3),
      SpreadsheetCell::Text(String::from("blue")),
      SpreadsheetCell::Float(10.12),
  ];
  ```
- Vector drop scope:
  ```rust
  {
      let v = vec![1, 2, 3, 4];

      // do stuff with v
  } // <- v goes out of scope and is freed here
  ```

#### Comparisons

- `Vec::new` vs `vec!`: empty vector constructor often needs type annotation; macro with initial values usually lets Rust infer the type.
- `Vec<T>` vs built-in array at CH-08 level: vectors are heap-backed, variable-length collections; arrays are built-in fixed-size collections from earlier chapters.
- `[]` vs `get`: `[]` returns a reference and panics if out of range; `get` returns `Option<&T>` and gives `None` if out of range.
- Valid index vs invalid index: valid access gives an element reference or `Some(&element)`; invalid `[]` panics and invalid `get` returns `None`.
- Immutable iteration vs mutable iteration: `&v` allows reading elements; `&mut v` allows changing elements.
- Element mutation vs vector structure mutation: changing `*i` during mutable iteration changes element values; inserting/removing changes the vector structure and conflicts with the loop's borrow.
- Same Rust type vs different logical variants: vectors require one Rust element type; enum variants let different logical forms share one enum type.
- Enum variant vector vs trait object vector: enum works when allowed variants are known exhaustively; trait objects are for unknown or open sets of types.
- Dropping a scalar variable vs dropping a vector: dropping a vector also drops its contained elements.

### Card Content Candidates

#### Concepts

- New Rustaceans often get stuck on strings because Rust exposes possible errors, strings are complex data structures, and UTF-8 adds complexity.
- Strings are discussed as collections because they are implemented as a collection of bytes plus methods for interpreting those bytes as text.
- `String` supports collection-like operations such as creating, updating, and reading.
- `String` differs from other collections because indexing is complicated by the gap between human and computer interpretations of text.
- Rust has one string type in the core language: `str`.
- `str` is usually seen in borrowed form as `&str`.
- String slices are references to UTF-8 encoded string data stored elsewhere.
- String literals are stored in the program binary and are string slices.
- `String` is provided by the standard library rather than the core language.
- `String` is growable, mutable, owned, and UTF-8 encoded.
- Rustaceans may use "strings" to mean either `String` or `&str`.
- Both `String` and string slices are UTF-8 encoded.
- `String` is implemented as a wrapper around a vector of bytes with extra guarantees, restrictions, and capabilities.
- `String::new` creates a new empty `String`.
- `to_string` creates a `String` from a value implementing `Display`, such as a string literal.
- `String::from` creates a `String` from a string literal.
- For the string-literal examples, `String::from` and `to_string` do the same thing; choosing between them is style and readability.
- `String` can contain any properly encoded UTF-8 data.
- A `String` can grow and change like a `Vec<T>` when data is pushed into it.
- `push_str` appends a string slice to a `String`.
- `push_str` takes a string slice so it does not need to take ownership of the argument.
- Listing 8-16 can still print `s2` after `s1.push_str(s2)` because `push_str` did not take ownership of `s2`.
- `push` appends a single `char` to a `String`.
- The `+` operator can concatenate strings, but its ownership behavior matters.
- `s1 + &s2` moves `s1`, borrows `s2`, and returns a new `String`.
- The `+` operator uses the `add` method.
- The simplified `add` signature is `fn add(self, s: &str) -> String`.
- The right operand is a string slice because the `add` parameter is `&str`.
- `&String` can be coerced to `&str` by deref coercion, turning `&s2` into `&s2[..]`.
- `add` takes ownership of `self`, so `s1` is no longer valid after `s1 + &s2`.
- The `+` operation is more efficient than it looks: it takes ownership of `s1`, appends a copy of `s2`'s contents, and returns ownership of the result.
- Chaining `+` for several strings can become hard to read.
- `format!` works like `println!` but returns a `String` instead of printing.
- `format!` uses references and does not take ownership of its parameters.
- Rust strings do not support integer indexing.
- Listing 8-19 fails with E0277 because `str` cannot be indexed by an integer.
- Rust prevents integer string indexing to avoid returning unexpected byte values or invalid characters.
- `String` is a wrapper over `Vec<u8>`.
- `"Hola"` has length 4 because each Latin letter takes 1 byte in UTF-8.
- `"Здравствуйте"` has length 24 bytes even though a human might count 12 letters, because each Unicode scalar value in that string takes 2 bytes.
- A byte index into a string does not always correspond to a valid Unicode scalar value.
- The first byte of `З` is `208` and the second is `151`; `208` alone is not a valid character.
- If `&"hi"[0]` returned a byte value, it would return `104`, not `h`, which is generally not what users want.
- Rust refuses to compile integer string indexing to prevent misunderstandings early.
- Rust discusses three useful views of UTF-8 strings: bytes, scalar values, and grapheme clusters.
- Bytes are the raw `u8` values computers store.
- Unicode scalar values are what Rust's `char` type represents.
- Grapheme clusters are the closest thing to human-perceived letters.
- The Hindi word "नमस्ते" is stored as 18 bytes.
- As Unicode scalar values, "नमस्ते" is six `char` values: `['न', 'म', 'स', '्', 'त', 'े']`.
- Some scalar values in that Hindi example are diacritics that do not make sense on their own.
- As grapheme clusters, "नमस्ते" is four human-perceived letters: `["न", "म", "स्", "ते"]`.
- Rust lets each program choose the interpretation of string data it needs.
- String integer indexing also conflicts with the expectation that indexing is O(1).
- Rust cannot guarantee O(1) character lookup in a `String` because it would need to walk from the beginning to count valid characters.
- A range string slice such as `&hello[0..4]` selects bytes and returns `&str`.
- With `let hello = "Здравствуйте";`, `&hello[0..4]` is `Зд` because each of those characters is 2 bytes.
- Slicing only part of a character's bytes, such as `&hello[0..1]`, panics at runtime.
- String slicing with byte ranges should be used cautiously because invalid boundaries can crash a program.
- The best way to operate on string pieces is to be explicit about whether bytes or characters are needed.
- `.chars()` iterates over Unicode scalar values.
- `.bytes()` iterates over raw bytes.
- `"Зд".chars()` yields `З` and `д`.
- `"Зд".bytes()` yields `208`, `151`, `208`, and `180`.
- Valid Unicode scalar values may be made of more than one byte.
- Grapheme cluster functionality is not provided by the standard library; crates are available on crates.io.
- Rust chooses correct `String` data handling as the default, requiring more up-front thought about UTF-8.
- This tradeoff helps prevent errors involving non-ASCII characters later.
- The standard library offers methods on `String` and `&str`, including `contains` and `replace`.

### Card Content Candidates

#### Concepts

- `HashMap<K, V>` stores a mapping of keys of type `K` to values of type `V`.
- A hash map uses a hashing function to determine how keys and values are placed into memory.
- Other languages may call similar structures hashes, maps, objects, hash tables, dictionaries, or associative arrays.
- Hash maps are useful when data should be looked up by a key rather than by numeric index.
- In the team-score example, keys are team names and values are scores.
- `HashMap` has many standard-library methods beyond the basic API covered in this section.
- `HashMap` must be brought into scope with `use std::collections::HashMap;`.
- `HashMap` is not included in the prelude because it is the least often used of the three common collections in CH-08.
- The standard library has no built-in macro to construct hash maps in this section.
- Hash maps store data on the heap.
- Hash maps are homogeneous in key and value types.
- All keys in one hash map must have the same type.
- All values in one hash map must have the same type.
- `HashMap::new()` creates an empty hash map.
- `insert` adds key-value pairs.
- In Listing 8-20, `scores` has `String` keys and `i32` values.
- `get` retrieves a value by key.
- `get` returns `Option<&V>`.
- If a key is absent, `get` returns `None`.
- Listing 8-21 uses `copied()` to convert `Option<&i32>` to `Option<i32>`.
- Listing 8-21 uses `unwrap_or(0)` to use zero when the key is missing.
- Hash maps can be iterated with `for (key, value) in &scores`.
- Hash map iteration order is arbitrary.
- Values of `Copy` types, such as `i32`, are copied into the hash map.
- Owned values, such as `String`, are moved into the hash map.
- After `map.insert(field_name, field_value)`, the hash map owns those `String` values and the original variables are invalid.
- If references are inserted into a hash map, the referenced values are not moved.
- Referenced values inserted into a hash map must remain valid at least as long as the hash map.
- Each unique key can have only one value associated with it at a time.
- Multiple keys may have the same value.
- Updating a hash map requires deciding what to do when a key already has a value.
- One update strategy is replacing the old value with the new value.
- One update strategy is keeping the old value and ignoring the new value.
- One update strategy is combining the old value and new value.
- Calling `insert` twice with the same key replaces the previous value.
- Listing 8-23 inserts `"Blue"` with `10`, then `"Blue"` with `25`, leaving one key-value pair.
- `entry` checks whether a key already exists in the hash map.
- `entry` returns an `Entry` enum representing a value that might or might not exist.
- `or_insert` returns a mutable reference to the existing value if the key exists.
- `or_insert` inserts its argument as the new value and returns a mutable reference to it if the key is absent.
- The `entry`/`or_insert` API is cleaner than writing the conditional logic manually and plays better with the borrow checker.
- Listing 8-24 inserts `"Yellow"` with `50` because it is absent.
- Listing 8-24 does not change `"Blue"` because it already has `10`.
- Listing 8-25 counts words by using words as keys and counts as values.
- `split_whitespace` returns an iterator over whitespace-separated subslices of `text`.
- In the word-count example, `or_insert(0)` inserts a count of zero the first time a word appears.
- `or_insert` returns `&mut V`, stored as `count` in Listing 8-25.
- Updating the count requires dereferencing `count` with `*count += 1`.
- The mutable reference from `or_insert` goes out of scope at the end of each loop iteration, so the updates are safe under borrowing rules.
- By default, `HashMap` uses SipHash.
- SipHash can provide resistance to denial-of-service attacks involving hash tables.
- SipHash is not the fastest hashing algorithm, but the security/performance tradeoff is worthwhile by default.
- If profiling shows the default hash function is too slow, a different hasher can be specified.
- A hasher is a type that implements the `BuildHasher` trait.
- Crates.io has libraries that provide hashers implementing many common hashing algorithms.
- CH-08 practice prompts include median/mode with a vector and hash map, Pig Latin string conversion, and a company department text interface using hash maps and vectors.
- CH-08 summary: vectors, strings, and hash maps provide core functionality for storing, accessing, and modifying data.

#### Syntax Forms

- Import and create a hash map:
  ```rust
  use std::collections::HashMap;

  let mut scores = HashMap::new();
  ```
- Insert key-value pairs:
  ```rust
  scores.insert(String::from("Blue"), 10);
  scores.insert(String::from("Yellow"), 50);
  ```
- Read a value with fallback:
  ```rust
  let team_name = String::from("Blue");
  let score = scores.get(&team_name).copied().unwrap_or(0);
  ```
- Iterate over key-value pairs:
  ```rust
  for (key, value) in &scores {
      println!("{key}: {value}");
  }
  ```
- Owned key/value move into a hash map:
  ```rust
  let field_name = String::from("Favorite color");
  let field_value = String::from("Blue");

  let mut map = HashMap::new();
  map.insert(field_name, field_value);
  ```
- Overwrite a value:
  ```rust
  let mut scores = HashMap::new();

  scores.insert(String::from("Blue"), 10);
  scores.insert(String::from("Blue"), 25);

  println!("{scores:?}");
  ```
- Insert only if absent with `entry` and `or_insert`:
  ```rust
  let mut scores = HashMap::new();
  scores.insert(String::from("Blue"), 10);

  scores.entry(String::from("Yellow")).or_insert(50);
  scores.entry(String::from("Blue")).or_insert(50);

  println!("{scores:?}");
  ```
- Word-count update based on old value:
  ```rust
  let text = "hello world wonderful world";

  let mut map = HashMap::new();

  for word in text.split_whitespace() {
      let count = map.entry(word).or_insert(0);
      *count += 1;
  }

  println!("{map:?}");
  ```
