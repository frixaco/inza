### Learning Objectives

- Learner can state Rust's core design challenge from the Introduction: combining high-level ergonomics and low-level control.
- Learner can explain what Rust means by low-level control in this context: control over details such as memory usage without the traditional hassle.
- Learner can identify Rust's broad goals: faster, more reliable software; safety and productivity; speed and ergonomics.
- Learner can explain the compiler's gatekeeper role for teams: refusing to compile code with subtle bugs, including concurrency bugs, so developers can focus on program logic.
- Learner can distinguish concept chapters from project chapters and name the project chapters: Chapters 2, 12, and 21.
- Learner can explain why the book uses compiler feedback as a teaching tool, including examples that intentionally do not compile, panic, or produce undesired behavior.
- Learner can use the Introduction's roadmap to locate major topics: ownership in Chapter 4, `match`/`if let`/`let...else` in Chapter 6, async in Chapter 17, advanced unsafe/macros topics in Chapter 20, and editions in Appendix E.

### Card Content Candidates

#### Concepts

- Rust's introductory promise: write faster, more reliable software while balancing powerful technical capacity with developer experience.
- Tradeoff Rust challenges: high-level ergonomics and low-level control are often opposed in language design; Rust aims to offer both.
- Low-level control example: memory usage is a detail Rust lets programmers control without the usual burden associated with such control.
- Teams: Rust helps large teams with mixed systems programming experience because the compiler rejects elusive bugs before the program runs.
- Compiler as collaborator: by working alongside compiler checks, teams can spend more time on program logic and less time chasing subtle bugs.
- Tooling in systems programming: Cargo manages dependencies and builds; `rustfmt` standardizes style; the Rust Language Server provides IDE integration, completion, and inline errors.
- Students: Rust is positioned as a way to learn systems concepts, including operating systems development, with community support.
- Companies: the Introduction lists production uses including command line tools, web services, DevOps tooling, embedded devices, media analysis/transcoding, cryptocurrencies, bioinformatics, search engines, Internet of Things, machine learning, and Firefox.
- Speed has two meanings here: runtime speed and the speed at which Rust lets developers write programs.
- Stability: compiler checks help keep code stable through feature additions and refactoring.
- Zero-cost abstractions: higher-level features should compile to lower-level code as fast as manually written code.
- Broad ambition: eliminate accepted tradeoffs by providing safety and productivity, speed and ergonomics.
- Book audience: assumes prior programming experience but no specific programming language.
- Reading model: later chapters build on earlier chapters; some topics are introduced lightly and revisited with detail later.
- Book chapter types: concept chapters teach aspects of Rust; project chapters build small programs applying prior material.
- Project chapters named by the Introduction: Chapter 2 guessing game, Chapter 12 `grep`-like command line tool, Chapter 21 low-level multithreaded web server.
- Compiler feedback workflow: learning Rust includes learning to read compiler error messages because they guide the learner toward working code.
- Example status markers: some examples intentionally do not compile, panic, or produce undesired behavior; the surrounding text and marker table explain which case applies.
- Source availability: the book source files are available on GitHub.

#### Failure Modes

- Misreading intentionally broken examples as mistakes in the book or deck; final cards must preserve whether source examples are meant not to compile.
- Treating "Rust is fast" as only runtime speed; the Introduction also uses speed for development pace.
- Treating Rust as only syntax and libraries; the Introduction frames ownership, compiler feedback, tools, systems concepts, and project practice as part of learning Rust.

#### Comparisons

- High-level ergonomics vs low-level control: Rust aims to balance these instead of forcing a choice.
- Safety/productivity and speed/ergonomics: the Introduction presents these as pairs Rust tries to provide together.
- Concept chapters vs project chapters: concept chapters teach an aspect of Rust; project chapters build small programs that apply earlier material.
- Chapter 2 path vs Chapter 3 path: hands-on learners can start with the guessing game; detail-first learners can skip to common programming concepts and return later.
- Compile error vs panic vs undesired behavior: three distinct categories marked by the book's Ferris table.
- Runtime speed vs development speed: both are part of what the Introduction means by speed.
