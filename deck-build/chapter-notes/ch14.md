### Card Content Candidates

#### Concepts

- Release profiles are predefined profiles.
- Release profiles are customizable profiles.
- Release profiles contain different configurations for compiling code.
- Release profiles give programmers more control over compile options.
- Each profile is configured independently of the others.
- Cargo's two main profiles are `dev` and `release`.
- Cargo uses the `dev` profile when running `cargo build`.
- Cargo uses the `release` profile when running `cargo build --release`.
- The `dev` profile has good defaults for development.
- The `release` profile has good defaults for release builds.
- Build output can show which profile Cargo used.
- Example `cargo build` output says `Finished 'dev' profile [unoptimized + debuginfo]`.
- Example `cargo build --release` output says `Finished 'release' profile [optimized]`.
- Cargo has default settings for each profile.
- Profile defaults apply when the project has no explicit `[profile.*]` sections in `Cargo.toml`.
- Adding a `[profile.*]` section customizes that profile.
- A profile section can override a subset of defaults.
- Unspecified profile settings continue to use their defaults.
- `opt-level` controls how many optimizations Rust applies to code.
- The `opt-level` range in this section is `0` to `3`.
- More optimizations increase compilation time.
- During development, faster repeated compilation is usually more important than maximum runtime speed.
- The default `dev` profile `opt-level` is `0`.
- Release builds are usually compiled less often but run many times.
- Release mode trades longer compile time for faster runtime code.
- The default `release` profile `opt-level` is `3`.
- Setting `[profile.dev] opt-level = 1` applies more optimizations than the default development build.
- Setting `[profile.dev] opt-level = 1` applies fewer optimizations than the default release build.
- Cargo's profile documentation contains the full list of configuration options and defaults.

#### Syntax Forms

- Build commands and profile output:
  ```console
  $ cargo build
      Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.00s
  $ cargo build --release
      Finished `release` profile [optimized] target(s) in 0.32s
  ```
- Default `opt-level` values shown in `Cargo.toml` form:
  ```toml
  [profile.dev]
  opt-level = 0

  [profile.release]
  opt-level = 3
  ```
- Override development optimization level:
  ```toml
  [profile.dev]
  opt-level = 1
  ```
- Profile section shape:
  ```toml
  [profile.<name>]
  key = value
  ```

- Given output containing `Finished 'release' profile [optimized]`, identify it as a release-profile build.
- Given no `[profile.*]` section in `Cargo.toml`, predict Cargo uses default profile settings.
- Given `[profile.dev] opt-level = 1`, predict `cargo build` uses the `dev` defaults plus the custom `opt-level`.
- Given `[profile.dev] opt-level = 1`, predict development builds apply more optimization than default `dev` but less than default `release`.
- Given a desire for faster repeated development builds, choose a lower optimization level.
- Given a desire for faster runtime code in a release build, choose a higher optimization level.
- Given a partial profile override, predict unspecified settings remain at their defaults.

#### Comparisons

- `dev` profile vs `release` profile: `dev` is used by `cargo build` and favors development defaults; `release` is used by `cargo build --release` and favors optimized release builds.
- Default `dev` `opt-level` vs default `release` `opt-level`: `0` vs `3`.
- Compile time vs runtime speed: more optimization extends compilation time but can make the resulting code run faster.
- Development builds vs release builds: development builds happen often and benefit from faster compilation; release builds may compile longer because the resulting program is expected to run many times.
- Default settings vs explicit profile sections: defaults apply automatically; `[profile.*]` sections override selected settings.

#### Syntax Forms

- Custom command binary naming convention:
  ```text
  cargo-something
  ```
- Run the custom Cargo command:
  ```console
  $ cargo something
  ```
- List Cargo commands, including custom commands:
  ```console
  $ cargo --list
  ```
- Install a Cargo extension, then run it as a subcommand:
  ```text
  cargo install <package-providing-cargo-something>
  cargo something
  ```
