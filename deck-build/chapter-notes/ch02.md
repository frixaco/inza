### Learning Objectives

- Learner can describe the guessing game behavior: generate a secret number from 1 through 100, accept guesses, report too low or too high, and exit on a correct guess.
- Learner can create and run the project with Cargo using `cargo new guessing_game`, `cd guessing_game`, and `cargo run`.
- Learner can bring `std::io` into scope with `use std::io` and explain why non-prelude items need `use`.
- Learner can create a mutable `String` buffer with `let mut guess = String::new();`.
- Learner can read terminal input with `io::stdin().read_line(&mut guess)` and explain why the argument is a mutable reference.
- Learner can explain why `read_line` appends to the target `String` instead of overwriting it.
- Learner can handle the `Result` returned by `read_line` with `expect`, including the `Ok` and `Err` behavior.
- Learner can use `println!` placeholders for captured variables and positional expression output.
- Learner can add `rand = "0.8.5"` to `Cargo.toml` and explain Cargo's dependency resolution, SemVer constraint, registry download, and lockfile behavior.
- Learner can use `use rand::Rng`, `rand::thread_rng()`, and `.gen_range(1..=100)` to generate an inclusive random number.
- Learner can compare a guess with the secret number using `guess.cmp(&secret_number)`, `std::cmp::Ordering`, and `match` arms for `Less`, `Greater`, and `Equal`.
- Learner can diagnose why Listing 2-4 does not compile: `guess` is a `String`, but `secret_number` is numeric, causing an E0308 mismatched-types error.
- Learner can shadow `guess` after trimming and parsing input: `let guess: u32 = guess.trim().parse().expect("Please type a number!");`.
- Learner can explain why `parse` needs a type annotation and why the `u32` annotation also lets Rust infer `secret_number` as `u32`.
- Learner can use `loop` to allow repeated guesses and `break` inside the winning `match` arm to exit.
- Learner can handle invalid numeric input with `match guess.trim().parse()`, `Ok(num) => num`, and `Err(_) => continue`.

### Card Content Candidates

#### Concepts

- Chapter 2 is a project chapter that introduces `let`, `match`, methods, associated functions, external crates, mutable variables, references, enums, and error handling at a high level before later chapters explain them in depth.
- Game contract: choose a random integer between 1 and 100, prompt for a guess, print whether it is too low or too high, print a win message on a correct guess, and exit.
- Cargo setup: `cargo new guessing_game` creates the project, and `cd guessing_game` enters it.
- `cargo run` builds and runs in one step, which supports rapid iteration on this project.
- `use std::io;`: brings the standard library `io` module into scope for input/output features.
- Prelude boundary: Rust automatically imports a set of standard library items called the prelude; items outside the prelude need explicit `use`.
- `main`: entry point of the program.
- `println!`: macro that prints strings, prompts, captured variables, and formatted expression results.
- `let mut guess = String::new();`: binds a mutable variable named `guess` to a new empty `String`.
- Variables are immutable by default; `mut` makes a binding mutable.
- `String`: standard-library type for growable UTF-8 text.
- `String::new`: associated function on `String` that creates a new empty string.
- `::`: syntax for accessing an associated function on a type, as in `String::new`.
- `io::stdin()`: returns a `std::io::Stdin` handle to terminal standard input.
- `.read_line(&mut guess)`: reads user input from standard input and appends it into the provided string.
- `read_line` appends instead of overwriting, so callers pass the destination string to be modified.
- `&mut guess`: mutable reference, needed because `read_line` changes the string contents.
- References are immutable by default; this example needs `&mut guess` instead of `&guess`.
- `read_line` returns `Result`, an enum that encodes error-handling information.
- `Result` variants: `Ok` means success and contains the generated value; `Err` means failure and contains error information.
- `expect`: on `Err`, crashes with the provided message; on `Ok`, extracts and returns the contained value.
- `read_line` successful value: number of bytes in the user's input.
- Ignoring the `Result` from `read_line` compiles with an unused `Result` warning because a possible error was not handled.
- `println!("You guessed: {guess}")`: named variable capture in the format string.
- `{}` placeholder: empty placeholders are filled by comma-separated expressions after the format string, in order.
- `rand` crate: library crate used because random number generation is not in Rust's standard library in this chapter.
- Binary crate vs library crate: the guessing game is a binary crate; `rand` is a library crate used by other programs and not executed on its own.
- Add a dependency under `[dependencies]` in `Cargo.toml`, exactly `rand = "0.8.5"` for this tutorial.
- SemVer constraint: `0.8.5` is shorthand for `^0.8.5`, meaning at least 0.8.5 but below 0.9.0.
- Cargo registry: Cargo fetches dependency metadata and crates from the registry, which is a copy of Crates.io data.
- Transitive dependencies: adding `rand` also downloads and builds crates that `rand` depends on.
- Rebuild behavior: if dependencies and source do not change, `cargo build` has little or nothing to do; if only `src/main.rs` changes, Cargo rebuilds the local crate but reuses compiled dependencies.
- `Cargo.lock`: records resolved dependency versions for reproducible builds and is often checked into source control.
- `cargo update`: ignores the lockfile, finds latest versions that fit `Cargo.toml`, and rewrites `Cargo.lock`.
- To move outside the compatible SemVer range, change the version requirement in `Cargo.toml`.
- `use rand::Rng;`: imports the `Rng` trait, whose methods random number generators implement.
- `rand::thread_rng()`: returns a random number generator local to the current thread and seeded by the operating system.
- `gen_range(1..=100)`: method from the `Rng` trait that generates an inclusive-range number from 1 through 100.
- `cargo doc --open`: builds local documentation for dependencies and opens it in a browser.
- Development-only secret print: printing `secret_number` helps test random generation, but it must be removed from the final game.
- `std::cmp::Ordering`: enum with `Less`, `Greater`, and `Equal` variants for comparison outcomes.
- `cmp`: compares two values and returns an `Ordering`; it takes a reference to the value to compare with.
- `match`: expression made of arms; each arm has a pattern and code that runs when the matched value fits that pattern.
- Match arm order matters for search, but the expression stops after the first successful match.
- Listing 2-4 is intentionally non-compiling because it compares `String` input to a numeric secret.
- Rust has a strong, static type system with type inference.
- Numeric default: without more information, Rust defaults integer literals here to `i32`.
- String-to-number conversion: trim the input string and parse it into a numeric type before comparing.
- Shadowing: Rust lets a new `guess` binding reuse the previous name, useful for converting from one type to another.
- `trim`: removes leading/trailing whitespace, including the newline from pressing enter and Windows `\r\n`.
- `parse`: converts a string into another type and returns a `Result` because parsing can fail.
- Type annotation syntax: `let guess: u32 = ...`; the colon introduces the variable's type.
- `u32`: unsigned 32-bit integer and a good default for a small positive number in this program.
- The `u32` annotation on `guess` plus comparison with `secret_number` makes Rust infer `secret_number` as `u32`.
- `loop`: keyword that creates an infinite loop.
- `break`: exits the loop; in this program, exiting the loop also exits `main` because the loop is the last part of the function.
- Invalid input before Listing 2-5: non-number input causes `parse().expect(...)` to panic.
- Invalid input in Listing 2-5: `match` on `parse` changes behavior from crashing to ignoring invalid guesses.
- `Ok(num) => num`: extracts the parsed number and yields it as the new `guess`.
- `Err(_) => continue`: matches any parse error and jumps to the next loop iteration.
- `_`: catch-all pattern used when the contained error value is not needed.
- Final cleanup: remove the `println!` that prints the secret number so the final game does not reveal the answer.

  ```rust
  use std::cmp::Ordering;
  use std::io;

  use rand::Rng;

  fn main() {
      println!("Guess the number!");

      let secret_number = rand::thread_rng().gen_range(1..=100);

      loop {
          println!("Please input your guess.");

          let mut guess = String::new();

          io::stdin()
              .read_line(&mut guess)
              .expect("Failed to read line");

          let guess: u32 = match guess.trim().parse() {
              Ok(num) => num,
              Err(_) => continue,
          };

          println!("You guessed: {guess}");

          match guess.cmp(&secret_number) {
              Ordering::Less => println!("Too small!"),
              Ordering::Greater => println!("Too big!"),
              Ordering::Equal => {
                  println!("You win!");
                  break;
              }
          }
      }
  }
  ```

#### Failure Modes

- Treating `use std::io;` as optional while still calling `io::stdin()`; without the import, use `std::io::stdin()`.
- Forgetting `mut` on `guess`, which is needed because input changes the string.
- Passing `&guess` instead of `&mut guess` to `read_line`.
- Ignoring `Result` from `read_line`; the compiler warns because the operation may fail.
- Assuming `expect` recovers from errors; it panics on `Err`.
- Assuming `read_line` replaces existing string contents; it appends.
- Forgetting `rand::Rng`; the trait must be in scope to use `gen_range`.
- Using a `rand` version outside `0.8.x` while following tutorial code; the examples assume the 0.8 API.
- Comparing the unparsed `String` guess directly with the numeric `secret_number`.
- Forgetting the type annotation on `parse`; Rust needs to know the target type.
- Forgetting to `trim` before parsing; newline or carriage-return/newline from pressing enter would prevent numeric parsing.
- Using `expect` on parse in the loop if invalid input should be ignored.
- Forgetting `break` in the correct-guess arm, causing the game to continue after a win.
- Leaving the development-only secret-number print in the final game.
- Treating `cargo update` as able to cross incompatible version requirements without editing `Cargo.toml`.

#### Comparisons

- Prelude item vs explicit import: prelude items are automatically available; `std::io` needs `use`.
- Variable immutability vs `mut`: immutable bindings cannot be changed; `let mut guess` permits mutation.
- Associated function vs method: `String::new()` is associated with the `String` type; `.read_line(...)` and `.gen_range(...)` are methods called on values.
- `String::new()` vs `read_line`: create an empty growable string vs append terminal input into it.
- `&guess` vs `&mut guess`: immutable reference vs mutable reference.
- `Ok` vs `Err`: success carrying a value vs failure carrying error information.
- `expect` on `read_line` vs `match` on `parse`: crash with message on error vs choose behavior for success and failure.
- Named placeholder `{guess}` vs empty placeholder `{}`: named variable capture vs expression list substitution.
- Binary crate vs library crate: executable guessing game vs reusable `rand` crate.
- Direct dependency vs transitive dependency: `rand` is listed directly; Cargo also downloads crates `rand` needs.
- `Cargo.toml` version requirement vs `Cargo.lock` resolved version: requested compatible range vs exact locked versions used for reproducibility.
- `cargo build` vs `cargo update`: build uses locked versions if present; update refreshes lockfile within manifest constraints.
- `1..=100` vs exclusive ranges: inclusive lower and upper bounds, so both 1 and 100 are possible.
- `Ordering::Less`, `Ordering::Greater`, `Ordering::Equal`: too small, too big, and win outcomes.
- String comparison failure vs numeric comparison success: parse input into `u32` before `cmp`.
- Shadowing vs separate variable names: reuse `guess` for the parsed number instead of creating `guess_str` and `guess`.
- Panic-on-invalid-input version vs continue-on-invalid-input version.
- Infinite `loop` vs `break` on success.
- Development build with secret print vs final game without secret print.
