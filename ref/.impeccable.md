# Design Context

## Users

Power users studying with Anki flashcards daily — language learners, medical students, art historians, programmers. They open this app multiple times per day for focused, efficient review sessions. They are frustrated with Anki's Qt-based UI (ugly default buttons, artifacts, non-native feel) and want a tool that respects their time and attention.

## Brand Personality

**Quiet, refined, efficient.**

The interface should feel like a premium native tool that gets out of the way. No celebration animations, no gamification, no distractions. The app is a workspace, not a toy. Trustworthy and calm.

## Aesthetic Direction

**Native macOS desktop GUI language.** Not a web app pretending to be native with fake traffic lights, but a web app that fully adopts macOS conventions: SF Pro typography, warm neutral palette, precise 8px grid spacing, translucent materials, native table/list views, sidebar source lists, and toolbar layouts. Think Apple Mail, Things 3, or Apple Notes — not a website.

## Design Principles

1. **Respect user attention** — quiet, non-intrusive UI. No popups, no badges demanding attention, no auto-playing animations.
2. **Information at a glance** — dense but not cluttered. Every stat a power user needs is visible without clicking.
3. **Keyboard-first** — every action has a keyboard shortcut. The app should feel fully controllable without a mouse.
4. **Authentic native feel** — use system conventions (sidebar + main area, native tables, toolbars, status bars) rather than web patterns (cards, hero sections, modals).
5. **Editorial typography** — contrast between serif display (for the brand mark) and sans-serif UI text creates a sense of craft and intention.

## Technical Notes

- Light mode primary, with full dark mode support via CSS variables
- No fake window chrome (traffic lights) — just authentic native design language
- Minimum viewport: 900px (desktop app assumption)
- Uses system fonts exclusively (`-apple-system`, `ui-serif`)
